並列で調べさせて、報告を型で揃えて、別エージェントで裏取りして、結論＋住所だけ受け取る——ここまでは「**うまくいったとき**」の話でした。けれど何体も並列で回していると、遅かれ早かれぶつかるのが「**10体投げて、9体は返ってきたのに1体だけ落ちている**」状況です。この記事は、子が1体こけても全体を止めず、失敗した分だけを拾い直す受け渡しの話です。

> これは[「報告を構造化して並列集計する」](https://qiita.com/StreamSolty/items/bd039b8004d9420dd96d)[「独立した検証で裏取りする」](https://qiita.com/StreamSolty/items/0fda2216380f4b0391a8)[「親のコンテキストを汚さず受け渡す」](https://qiita.com/StreamSolty/items/7979d51402daf35d9c5c)話の続編です。前回までは**うまく返ってきた結果**の扱いでしたが、今回は**うまく返ってこなかったときに、どう振る舞わせるか**という異常系の設計です。

Claude Code（Anthropicの公式CLI）でサブエージェントを並列に走らせると、便利な反面、子は子で独立に動くので、**ある1体だけがタイムアウトしたり、途中で詰まって中途半端な結果を返したり**することが起きます。1体や2体なら珍しいことですが、10体・20体と数を増やすほど、「全部きれいに揃って返ってくる」確率はむしろ下がっていきます。

やっかいなのは、ここで素朴に組むと**1体の失敗が全体の失敗になりがち**なことです。9体ぶんの正しい調査が終わっているのに、1体こけたせいで「もう一回最初からやり直し」になる。あるいはもっと悪いのが、失敗した子が**黙って空っぽの結果を返し**、親がそれに気づかず「全部終わった」ことにしてしまうケースです。

この記事では、筆者が並列調査をエージェントに任せるなかで効いた、**「成功した分は確定させ、落ちた分だけ拾い直す」型**を紹介します。仕組みを丸ごと組む話ではなく、子への指示と親の受け取り方を少し変えるだけの、運用の割り切りの話です。

---

## まず：「全部成功する前提」で組んではいけない

最初にやりがちなのが、並列で投げて「**全部の結果が揃ったら次に進む**」と素朴に書くことです。これは数が増えると詰まります。

理由は2つです。

1. **数が増えるほど「全員成功」は起きにくい。** 1体あたりの成功率が高くても、10体・20体と掛け算になれば、どこか1体がこける確率は無視できなくなります。
2. **失敗が「見えない」ことがある。** 子が律儀に何か返してくると、それが「ちゃんとした結論」なのか「詰まって途中で諦めた空返事」なのか、親からは区別がつきにくい。一番怖いのは、エラーで止まることではなく、**失敗が静かに成功のフリをすること**です。

だから設計の出発点を、「全員成功するはず」ではなく「**何体かは落ちる前提。落ちたときどうするかを先に決めておく**」に置き換えます。

---

## 解決：成功分は確定、失敗分だけ投げ直す

並列で投げるとき、子への指示と親の受け取り方に「失敗したときの振る舞い」を最初から入れておくだけで、1体の失敗が全体を巻き込まなくなります。

### Before（1体こけたら全部やり直し）

```text
この10個の対象をそれぞれ調査して、全部終わったら結果をまとめてください。
```

→ 1体が途中で落ちると、9体ぶんの成功も含めて「うまくいかなかった」になり、最初から投げ直しになりがち。失敗が黙殺されれば、欠けたまま「完了」してしまう。

### After（成否を分けて、失敗分だけ拾い直す）

```text
この10個の対象をそれぞれ調査してください。各対象について、次の形で返してください。

- 対象: どれについての結果か
- 状態: 成功 / 失敗 のどちらか
- 結論: 成功なら1〜3行。失敗なら「何が・どこで・なぜ失敗したか」を1〜2行
- 根拠の住所: 確認したファイルのパス（成功時）

全部が成功する前提で書かないこと。落ちた対象は、無理に埋めず「失敗」と正直に書いてください。
最後に「成功した対象」と「失敗した対象」を分けて一覧にしてください。
```

成功と失敗を**最初から別物として返させる**だけで、親の手元には「3/10 成功・残り7件は理由つきで失敗」のような状態がそのまま残ります。あとは、**成功した分はそのまま確定**させ、**失敗した7件だけをもう一度投げ直せばいい**。9体ぶんの成果を捨てずに済みます。前回までの「返り値の境界を指示で決める」と同じで、**成否の境界も指示で決める**のがコツです。

## 一段上：失敗を「握りつぶさせない」報告と、リトライの上限

部分リトライを安全に回すには、もう2つだけ足します。

ひとつは、**失敗を握りつぶさせない**こと。子が詰まったときに、それらしい当たり障りのない結論で埋めてしまうのが一番危ないので、ここでも「**確認できなければ確認できずと書け**」を効かせます。

```text
途中で確認できなくなったら、推測でそれらしい結論を作らないこと。
「ここまでは確認できた／ここから先は確認できず」と、できた所とできない所の境界を書いてください。
```

もうひとつは、**リトライに上限を置く**こと。失敗分を投げ直すのは有効ですが、同じ指示でただ投げ直すと、同じ理由でまた落ちて、延々とループします。

```text
（親側の割り切り）
- 失敗した対象だけを、もう一度投げ直す（成功分は触らない）
- ただし同じ対象のやり直しは2回まで。
- 2回目も落ちたら、原因（対象が大きすぎる／情報が見つからない 等）を変えて投げる:
  対象をさらに分ける／別の調べ方を指示する など。
- それでも駄目なら「未達」として残し、人間に上げる。黙って欠けたまま完了にしない。
```

「成功分は確定」「失敗分だけ・上限つきで投げ直す」「同じ失敗には別アプローチ」——この3つで、1体の失敗が全体を道連れにすることも、リトライが無限に回ることもなくなります。

## 構造化・検証・受け渡しと地続き

これは前回までの型の延長線上にあります。

- **構造化報告**：成否を `状態` という1フィールドとして型に足すだけで、親は「成功◯件・失敗◯件」を機械的に仕分けできます。
- **独立検証**：失敗が「静かな嘘」に化けるのを防ぐのは、前回の裏取りと同じ発想です。怪しい結論は、住所を渡して検証側に確かめさせます。
- **コンテキストの受け渡し**：失敗報告も「**理由＋住所**」だけに絞れば、何体落ちても親は重くなりません。失敗の全ログを貼らせる必要はなく、「どこで・なぜ・どこを見れば分かるか」で十分です。

「並列 → 集計 → 裏取り → 軽い受け渡し」に、今回の「**落ちた分だけ拾い直す**」が加わると、数を増やしても崩れにくい回し方になります。

## 落とし穴：失敗の扱いを間違えると、静かに壊れる

異常系こそ、雑にやると逆効果になるので明記します。

| やりがち | なぜ危ないか | どうする |
|---|---|---|
| 失敗を黙って空で返させる | 欠けたまま「完了」になり、後で気づけない | 「失敗」と状態を必ず明示させる |
| 1体の失敗で全部やり直す | 成功した分まで捨ててコストが膨らむ | 成功分は確定、失敗分だけ投げ直す |
| 同じ指示でリトライし続ける | 同じ理由でまた落ち、無限ループ | 上限を置き、2回目は原因を変える |
| 失敗を全部そのまま人間に丸投げ | 自動で拾える分まで手作業に戻る | 自動リトライ→それでも駄目な分だけ人間へ |
| 取り返しのつかない操作を自動リトライ | 「消す・送る・公開する・課金する」を二重に走らせる危険 | 副作用のある操作は失敗時に止め、人間が確認 |

最後の一行はとくに大事です。**調査や要約のリトライは安全ですが、外に影響が出る操作（送信・公開・課金・削除）を勝手に投げ直させてはいけません。** ここは失敗したら止めて、人間が現物を見てから判断します。

## まとめ

| 型 | 要点 |
|---|---|
| 失敗前提で組む | 「全員成功」を前提にしない。落ちたときの振る舞いを先に決める |
| 成否を分けて返させる | `状態: 成功/失敗` を型に足し、成功分と失敗分を仕分ける |
| 成功分は確定 | 9体成功・1体失敗なら、9体は捨てずに確定させる |
| 失敗分だけ投げ直す | 落ちた分だけ・上限つきで、2回目は原因を変えて再実行 |
| 握りつぶさせない | 「確認できず」を必ず書かせ、静かな失敗を可視化する |
| 副作用は自動リトライ禁止 | 送信・公開・課金・削除は失敗時に止め、人間が確認 |

並列調査は「速く集める」「正しく裏取りする」「軽く受け渡す」だけでは足りません。**一部がこけても全体を止めず、落ちた分だけ拾い直す**ところまで決めて、はじめて数を増やしても崩れなくなります。

## まず1つだけ試すなら

仕組みを組む必要はありません。次に何かを並列で調べさせるとき、依頼の最後にこの一文を足すだけで十分です。

```text
各対象について「成功／失敗」を明記し、失敗したものは理由を1行で書いてください。
全部成功する前提で書かないこと。確認できなかったことは「確認できず」と書いてください。
最後に、成功した対象と失敗した対象を分けて一覧にしてください。
```

これだけで、戻ってくる結果が「成功◯件・失敗◯件（理由つき）」に分かれ、**失敗した分だけをもう一度投げ直す**だけで済むようになります。まずは一番よく回す並列調査から試してみてください。
