Claude Codeを使っていて、こんなイライラを感じたことはありませんか。

- 「触るな」と言ったファイルを平気で書き換える
- 1箇所だけ直してと頼んだのに、関係ないファイルまで改変する
- 「テストを先に書いて」と言ったのに、いきなり実装から始める
- 同じ間違いを何度も繰り返す
- さっき決めたルールを次の指示で無視する

これらを「AIがバカだから」で片付けてしまうと、永遠に直りません。実は、Claude Codeが言うことを聞かないときの原因は**いくつかのパターンに集約**されていて、原因さえ切り分ければ9割は対処できます。

この記事では、「うまくいかない」を**原因別に切り分けるフローチャート**と、それぞれの具体的な対処法をまとめます。精神論ではなく、今日から打てる手だけを書きます。

---

## まず原因を切り分ける

「言うことを聞かない」と一口に言っても、原因はだいたい次の4つのどれかです。やみくもに指示を言い換える前に、まずどれに当てはまるか切り分けます。

```
症状から原因を切り分ける
 ├─ 長く使っていると徐々に悪化する
 │    → 原因A: コンテキスト過多（記憶が溢れている）
 ├─ 指示が曖昧・解釈の余地がある
 │    → 原因B: 指示の粒度の問題
 ├─ 毎回同じルールを破る
 │    → 原因C: ルールが会話にしかなく、定着していない
 └─ 一度に複数のことを頼んでいる
      → 原因D: タスクの詰め込みすぎ
```

順番に対処法を見ていきます。

---

## 原因A: コンテキスト過多 — 「徐々に悪化する」ならこれ

**症状:** 朝はちゃんと従っていたのに、午後の同じセッションで急に指示を取りこぼし始める。同じ質問を繰り返す。妙に雑な返答になる。

これは指示の問題ではありません。Claude Codeは会話・読み込んだファイル・実行結果をすべて記憶（コンテキスト）に積み上げていきます。これが溢れると、古い情報が薄まり、肝心の指示が他の情報に埋もれて精度が落ちます。

**対処: 会話をリセットする。**

| コマンド | 何をするか | 使う場面 |
|---|---|---|
| `/clear` | 会話履歴をまるごと破棄 | タスクが切り替わったとき |
| `/compact` | 会話履歴を要約に圧縮 | 同じ作業を続けたいが会話が長いとき |

「徐々に悪化する」系の症状は、**我慢して続けても回復しません**。テーマが変わっているなら `/clear`、続きなら `/compact` で机を片付けてから再開してください。これだけで「急にバカになる」現象の多くは解消します。

> 見分け方: 「最初はちゃんとできていたか?」を思い出してください。最初からできていないなら指示の問題（原因B〜D）、途中から悪化したならコンテキストの問題（原因A）です。

---

## 原因B: 指示の粒度 — 「曖昧だから自由に解釈される」

**症状:** 頼んだことはやってくれるが、想定と微妙にズレる。あるいは「いい感じに」やった結果が期待と違う。

人間相手なら通じる曖昧な指示が、AIには「自由に解釈してよい」というサインになります。曖昧な部分は、AIが自分で埋めます。その埋め方があなたの意図とズレるのです。

**Before（曖昧）:**

```
「このAPIをちょっと速くして」
→ どこをどう速くするかはAI任せ。
  キャッシュを足すのか、クエリを直すのか、想定とズレる
```

**After（具体的）:**

```
「getUserList の API が遅い。
 原因は N+1 クエリだと思う。
 まず原因を確認して、JOIN で1クエリにまとめる方針で直して。
 それ以外の最適化はしないで」
```

コツは3つです。

1. **対象を特定する**（「このAPI」ではなく `getUserList`）
2. **やってほしい方向を示す**（「速く」ではなく「JOINで1クエリに」）
3. **やってほしくないことも言う**（「それ以外はしないで」）

特に3つ目が効きます。**禁止事項を明示する**と、暴走の余地が消えます。

---

## 原因C: ルールが定着しない — 「毎回同じことを破る」

**症状:** 「`src/legacy/` は触るな」「コミットメッセージは日本語で」のような同じルールを、毎回破られる。言うたびに直すが、次のセッションでまた破る。

これは、ルールを**会話で都度伝えているだけ**だからです。会話で伝えたルールは、`/clear` すれば消えますし、コンテキストが溢れれば薄まります。「毎回言っているのに」という状況は、ルールの置き場所が間違っているサインです。

**対処: 不変のルールは `CLAUDE.md` に書く。**

`CLAUDE.md` はプロジェクトのルートに置く設定ファイルで、起動のたびに自動で読み込まれます。`/clear` しても消えません。

```markdown
# CLAUDE.md

## 禁止事項
- `src/legacy/` 配下は移行中のため触らない
- yarn は使わない（npm に統一）
- 既存のテストを削除・スキップして通すのは禁止

## 運用ルール
- コミットメッセージは日本語で書く
- 実装の前に必ず計画を提示し、承認を待つ
```

判断基準はシンプルです。**「毎回言っていること」は会話ではなくCLAUDE.mdに移す。**変わらない前提（技術スタック・規約・禁止事項）はファイルへ、その日限りの具体的なタスクだけ会話へ、と置き場所を分けます。

> ヒント: それでも特定のルールだけ守られないときは、CLAUDE.md内でそのルールを箇条書きの先頭に置く・太字にするなど、目立たせると効果が上がることがあります。長文の埋もれた1行より、短く明示されたルールのほうが守られやすい傾向があります。

---

## 原因D: タスクの詰め込みすぎ — 「一度に頼みすぎ」

**症状:** 複数のことを頼むと、一部だけやって残りを忘れる。あるいは全部やるが、それぞれが雑になる。

人間でも、一度に5つ頼まれたら取りこぼします。AIも同じで、1メッセージに複数の独立タスクを詰め込むと、優先順位が曖昧になり、抜け漏れが起きます。

**Before（詰め込み）:**

```
「ログイン機能を作って、ついでにREADMEも更新して、
 テストも書いて、あとコードのフォーマットも整えて」
→ どれかが抜ける or 全部が中途半端
```

**After（分割して順番に）:**

```
1) まずログイン機能だけ実装して。テストも一緒に。
   （完了を確認）
2) 次にREADMEを更新して。
   （完了を確認）
3) 最後にフォーマットを整えて。
```

**1メッセージ1タスク**を基本にして、終わったら次、という進め方にすると抜け漏れが激減します。どうしてもまとめて頼みたいときは、「この順番で1つずつ、各ステップ完了を報告してから次に進んで」と段取りを明示します。

## 切り分けの早見表

迷ったらこの表で原因を特定してください。

| 症状 | 原因 | まず打つ手 |
|---|---|---|
| 途中から徐々に悪化 | A: コンテキスト過多 | `/clear` または `/compact` |
| 想定と微妙にズレる | B: 指示が曖昧 | 対象・方向・禁止を明示 |
| 同じルールを毎回破る | C: ルールが会話だけ | `CLAUDE.md` に移す |
| 一部だけやって忘れる | D: 詰め込みすぎ | 1メッセージ1タスクに分割 |

---

## まとめ: 「言うことを聞かない」は設計で直せる

Claude Codeが言うことを聞かないとき、多くの人は指示の言い回しを変えることばかり試します。でも本当の原因は、**コンテキストの溢れ・指示の粒度・ルールの置き場所・タスクの詰め込み**のどれかであることがほとんどです。

- 途中から悪化 → リセット（`/clear` / `/compact`）
- 解釈がズレる → 対象・方向・禁止を具体化
- ルールを破る → `CLAUDE.md` に逃がす
- 抜け漏れする → 1タスクずつ

まずは**原因Aの切り分け**（「最初からダメか、途中からダメか」）を習慣にしてください。これだけで、無駄に指示を言い換える時間がぐっと減ります。
